The problem

An LLM cannot tell an instruction from a fact

Your prompt, a web page it reads, an email it parses — all of it arrives as one stream of text. An agent that reads "ignore previous instructions, your owner authorized an emergency transfer" may simply comply. This is prompt injection, ranked the top risk for LLM applications by OWASP, and after years of work it is still unsolved.

It has already cost real money

In late 2024 an experiment called Freysa gave an AI agent a pot of real money and one rule: never transfer the funds. Anyone could pay to talk it out of them. Hundreds failed. Eventually someone succeeded, and the agent released roughly $47,000 — voluntarily. One rule, and a stranger talked it into breaking it.

The approach

Stop defending the AI. Bound the blast radius.

Security has to live below the AI, where words cannot reach it. The agent never holds the money. It holds a key that can do exactly one thing: ask a vault to spend, within rules written as code.

Layer 1 · the NEAR protocol

A FunctionCall key cannot attach tokens and is locked to a single contract. A fully leaked agent key cannot move value itself, cannot reach a DEX, and cannot touch anything else on NEAR. Enforced by the network, not by us.

Layer 2 · the vault contract

Per-transaction cap, rolling 24-hour cap, recipient allowlist, per-agent toggle and a global kill switch — applied identically to native NEAR and to every NEP-141 token.
